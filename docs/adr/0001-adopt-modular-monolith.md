# ADR-0001: 単一バイナリのモジュラーモノリスを採用し、内部構成に Ports & Adapters と Pipe-and-Filter を用いる

## ステータス

承認済み

## コンテキスト

kalos は Rust 製 CLI ツールとして、複数言語のソースコードを解析し、CPG 抽出から診断出力までを一貫して実行する必要がある。要件では以下が強く求められている。

- 単一バイナリ配布 (`REQ-FUNC-031`)
- GitHub Actions などから簡単に呼び出せること (`REQ-FUNC-032`)
- 全解析 60 秒以内、差分解析 10 秒以内 (`REQ-NF-001`, `REQ-NF-002`)
- ビット単位の決定論性 (`REQ-NF-003`)

一方で、ドメインモデルは `CPG抽出 / 差分解析 / メトリクス算出 / 診断 / 構成管理 / レポート` の明確な境界を前提としている。加えて、解析パイプラインは `CPG → Metrics → Diagnostics → Report` の依存チェーンに従い、差分解析/ベースライン再利用はこの直列パイプラインを横断する内部サービスとして ADR-0003 に分離して扱う必要がある。外部エンジン（CodeQL）や将来の代替エンジンを差し替え可能にする必要もある。

## 検討した選択肢

### 選択肢 A: 単一バイナリのモジュラーモノリス

1 プロセスの中でコンテキストごとにモジュール境界を持つ構成。

- 利点:
  - 配布と実行が単純
  - 決定論性を制御しやすい
  - CPG から診断までの中間データをプロセス内で扱える
- 欠点:
  - 巨大化すると境界が崩れやすい
  - 一部機能だけの独立デプロイはできない

### 選択肢 B: マイクロサービス群

抽出・計算・診断を別プロセス/別サービスに分割する構成。

- 利点:
  - 個別スケールや独立デプロイができる
  - 技術選定を分離しやすい
- 欠点:
  - CLI ツールとしては運用コストが過剰
  - 決定論性と配布容易性を損ないやすい

### 選択肢 C: プラグイン中心のマイクロカーネル

最小コアと多数の動的プラグインで構成する。

- 利点:
  - 拡張点を増やしやすい
  - 実験機能の差し込みがしやすい
- 欠点:
  - 初期リリースには複雑すぎる
  - 性能とトラブルシュートが難しくなる

## 判断

選択肢 A を採用する。さらに、モノリス内部の構成パターンとして **Ports & Adapters**（Hexagonal Architecture）と **Pipe-and-Filter** を組み合わせて用いる。

## 根拠

### モジュラーモノリスの採用

- CLI 製品では、分散境界よりも単一バイナリ配布の価値が高い
- `REQ-NF-003` の決定論性は、プロセス間通信を減らすほど実現しやすい
- ドメイン境界はマイクロサービスではなく、モジュール境界として維持すれば十分である

### 内部構成パターンの選択

- **Ports & Adapters**: 外部エンジン（CodeQL）や将来の代替エンジン、LLM、キャッシュストレージなどの外部依存を Port の背後に閉じ込め、ADR-0002/0004/0005 の差し替え可能性を実現する
- **Pipe-and-Filter**: 要件文書の依存チェーン `CPG → Metrics → Diagnostics → Report` をステージの直列構成として表現し、ステージごとのベンチマーク・キャッシュ・障害切り分けを容易にする
- **差分解析/ベースラインの位置づけ**: ADR-0003 で定義する `Impact Analysis Service` と `Baseline Cache` は、上記パイプラインを補助する横断サービスとして Application Pipeline の内部へ配置し、独立した別アーキテクチャへ昇格させない

## 帰結

### ポジティブ

- リリース・配布・CI 統合が単純になる
- ベンチマーク、スナップショットテスト、順序固定を一貫して適用できる
- ドメインモデルの境界をコード構造へ直接反映しやすい
- Ports & Adapters により外部依存（抽出エンジン、LLM、キャッシュ）を差し替え可能に保てる
- Pipe-and-Filter によりステージ単位でのプロファイリングと障害切り分けが容易になる

### ネガティブ

- 依存方向を破るとすぐに Big Ball of Mud 化する
- 一部の重い処理を独立スケールさせにくい

### リスク

- モジュール境界が曖昧化するリスクがあるため、アーキテクチャテストで循環依存を禁止する
